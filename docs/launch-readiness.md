Pusher / realtime — deterministic/local, code audit clean.** `/api/pusher/auth` fails closed (401 no session, 403 wrong tenant/channel, 400 malformed input); channel-name parsing is a strict regex with no partial/traversal matches; every publish call builds channel names from server-trusted IDs, never client input; publish is gated by `PROVIDER_SIDE_EFFECTS` (silent no-op when disabled); client-side dedupes events by ID (no duplicate-destructive-action risk; the only "realtime" actions are message appends/count refreshes); the public Pusher key cannot forge a channel-auth signature (the secret never reaches the client, confirmed by grep + a codebase-guard test). `tests/pusher-auth.test.ts` covers cross-tenant denial, malformed/crafted channel names (traversal, null bytes, injection), and the client-credential guard. **Not proven**: no live Production Pusher send/receive was exercised (the architecture here is platform/support messaging, not a customer-facing realtime board, so a live test would need a real support-conversation exchange — not attempted, low risk given the code audit).
