## 3. Data residency — Neon Production in AWS us-east-2 (Ohio)

**Conclusion: category B — a documented cross-border-transfer / EFVP obligation, not itself a prohibition and not a demonstrated launch blocker.**

Evidence: the CAI page states the enterprise "must proceed to a EFVP before communicating a personal information to an entity situated outside of Quebec", extends this to entrusting an outside-Québec party with the information on the enterprise's behalf, and describes a mandatory assessment plus a written agreement — not a ban on non-Québec hosting. The CAI Loi 25 page adds that communication is permitted only if the assessment shows adequate protection. Nothing in the sources opened requires hosting in Québec or Canada.

What follows for GarageOS (all already true for Vercel iad1, Supabase us-east-1, Pusher us2, Twilio US1, Resend US, Stripe US, so the DB is not the only US flow): (1) the EFVP in `privacy-impact-assessment.md` must be **completed and signed off before the first paying customer** — it is currently "Not complete"; (2) the written agreements (provider DPAs) must be filed — Neon's has not been located; (3) counsel decides the "adequate protection" conclusion for US processing (UNRESOLVED); (4) the public policy already discloses processing outside Québec/Canada. Moving the Neon project to a Canadian region is an **option, not a requirement**; it remains cheapest while there are zero real customers and was *not* done (out of scope; no Production migration). If the operator chooses to keep US hosting, record the decision and reasoning in PIA §7 item 2.
