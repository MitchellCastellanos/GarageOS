# GarageOS service-provider / subprocessor register

Internal register. Last full review: **2026-09-30**. Re-review at least every 6 months and whenever a provider, region, data category or feature changes (see ENGINEERING-RULES.md).
Do not publish location claims from this document until the "not verified" items are closed and legal review is done.

**Evidence levels used below**
- **INFRA** = read directly from our connected Vercel/Supabase accounts/repo on 2026-09-30.
- **DOC** = stated in the provider's official documentation. In this review the provider pages were reached through search-result summaries (and, for Supabase, the Supabase docs API); the primary page was not opened in a browser. Re-open the linked page before relying on a DOC fact contractually.
- **NV** = not verified. Never treat as fact.

GarageOS role: for shop-staff accounts and billing, GarageOS is the enterprise holding the information; for end-customer data entered by shops (customers, vehicles, invoices, photos, messages), GarageOS acts as the shops' service provider. The providers below are GarageOS's own service providers/subprocessors.

## Environment separation (INFRA, Vercel + repo, 2026-09-30; re-verified live via the Vercel API 2026-10-01 by Launch Agent 1 — superseded the MUST/SHOULD table below)
**History:** the Preview build of commit `d0eaddd` (branch `claude/storage-privacy-hardening`) once logged the Neon datasource and ran `prisma migrate resolve`, `prisma migrate deploy`, sender-identity backfill and super-admin bootstrap against the **production database**, because `npm run build` called `scripts/deploy-migrations.mjs` unconditionally and Preview shared `DATABASE_URL`. That was fixed in code (the script now skips all DB steps unless `VERCEL_ENV=production`, opt-in only via `RUN_DB_STEPS_ON_PREVIEW=1`) and — as of the live re-check below — in the Vercel project's environment variables as well. Preview URLs are behind Vercel Authentication/SSO (`ssoProtection.enabled=true`, `deploymentType: "all_except_custom_domains"` — confirmed via the Vercel API 2026-10-01; only the custom production domains `garage-os.ca`/`www.garage-os.ca` bypass SSO, every `*.vercel.app` deployment URL, Preview or Production, requires team SSO to view).

**2026-10-01 live re-check (read via the Vercel API, `filter_project_envs` — key/target/type only, no values decrypted or printed):** every variable this table used to mark MUST/SHOULD now has **separate Preview and Production records**, or is **absent from Preview entirely** (stricter than "separate"). This closes the environment-separation item in `docs/launch-readiness.md` #4b and `docs/provider-isolation.md` §6.

| Variable(s) | Live state (2026-10-01) | Note |
|---|---|---|
| `DATABASE_URL`, `DATABASE_URL_POOLED`, `DIRECT_URL` | **Separate** Preview/Production records (`DIRECT_URL` exists only for Preview; Production relies on `DATABASE_URL`/`DATABASE_URL_POOLED`, consistent with `docs/db-migrations.md`'s DIRECT_URL-falls-back-to-DATABASE_URL rule) | Matches the documented separate Neon branches (`preview`/`garageos_replay` vs. Production). |
